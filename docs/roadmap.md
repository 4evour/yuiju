# yuiju 长期规划

> 依据：[竞品调研报告](./research/competitor-landscape.md)（2026-08-18 快照）。
> 本文是方向性规划，不是排期承诺；每个阶段开工前仍按 AGENTS.md 流程先出技术方案再实现。

## 北极星

不做 AI 智能助手，做有自己生活的「人」。

产品终态：一个有长期记忆的开放性桌宠——她在一个持续推进的世界里自主生活，用户无论从 QQ、飞书还是桌面窗口看她，看到的都是同一个正在发生的真实生活。她的每句话都来自真实发生过的经历，她对每个用户都保有随时间演化的、属于她自己的记忆。

差异化定位（调研结论）：「常驻服务 + 单角色深度生活 + 真人长期共存 + 长期记忆」这个组合在开源界是空的。护城河不是任何单一功能，而是**世界的真实性**——行为历史、日记、计划构成的可追溯生活轨迹，无法用 prompt 现编。

## 路线总览

四个阶段，依赖关系单向：记忆 → 活力 → 形态 → 开放。每阶段有明确的「完成标志」，不达标志不进入下一阶段的 heavy 部分。

| 阶段 | 主题 | 核心问题 | 关键产出 |
|---|---|---|---|
| L1 | 长期记忆 | 她记得你吗 | 双时间轴记忆模型、记忆固化链路 |
| L2 | 长程活力 | 她活得下去吗 | 内驱力与目标生成、死循环根治 |
| L3 | 桌宠形态 | 她能在桌面上生活吗 | Tauri 桌宠壳、生活现场同步 |
| L4 | 生态开放 | 别人能住进这个世界吗 | 记忆协议、角色卡兼容 |

## L1：长期记忆（当前优先级最高）

### 为什么最先做

- 记忆是桌宠方向的前置依赖：没有长期记忆的桌宠只是聊天挂件（调研 §2.2 全行业缺失）。
- 失忆是全行业公认痛点（Open-LLM-VTuber 记忆下线重做、Replika 高频抱怨、KokoroMemo 因此单独成项目）。
- yuiju 已有别人没有的原料：行为历史（MongoDB）、模拟时间、日记、person-memory 按人组织的隔离。

### 目标机制（全部在现有 MongoDB + person-memory 上原生实现，不引入外部框架）

1. **双时间轴**：每条记忆记录「世界内发生时间（模拟时钟）」+「摄入时间（现实时钟）」。检索 recency 按模拟时间衰减——她按自己活过的时间回忆。涉及 `packages/utils/src/memory/` 的存储 schema 与 `memory-retrieval.ts` 排序。
2. **日记作为记忆固化链路**：日记（reflection 的落点）产生的提炼结果写入长期记忆，而不是只留在日记文本里。涉及 `packages/world/src/memory/diary/` 与 `episode-builder.ts` 的衔接。叙事自洽：睡前整理一天的记忆，等于免费的 sleep-time compute（Letta 机制的生活模拟变体）。
3. **分层记忆块**：常驻上下文的「角色自我认知 + 对每个用户的认知 + 关系当前状态」，限额管理。`core-memory.ts` 已有雏形，扩展为带版本的身体。
4. **ADD-only 不覆盖**：新事实不就地 UPDATE 旧事实，按时间线取当前有效值；旧版本保留（她记得半年前的你，是真实感来源）。
5. **importance 打分**：写入时 LLM 打分（1-10），供三因子检索（recency × importance × relevance）使用。
6. **双视角确认**：person-memory 中的「她对用户的认知」明确为她的主观表征，不是客观事实库；未来多角色时天然隔离。

### 完成标志（验收探针）

用 LoCoMo/LongMemEval 式探针问题验证：

- 时序：「我们上周三一起做了什么？」（模拟时间检索命中）
- 演化：「我现在还喜欢 X 吗 / 我以前喜欢什么？」（时间线取当前有效值）
- 多跳：「她第一次跟我提起打工是在什么背景下？」（记忆互链/多跳检索）
- 抗污染：错误信息不固化进长期记忆。

### 明确不做

- 不引入 mem0 / Graphiti / Letta / Neo4j（数据主权、成本、心智模型不匹配，调研 §3.3）。
- 不做自动遗忘/衰减删除（保留全部版本，检索侧用 recency 压低旧记忆权重）。

## L2：长程活力

### 为什么

死循环、日程漂移、目标达成后无事可做——全行业没解决（调研 §1.4），yuiju 已有实证（idle 分档恢复是对死循环的止血）。根治它就是领先行业的资产；不根治，桌宠形态会把问题放大到用户眼前（桌宠连续三天「发呆」是灾难）。

### 方向

1. **内驱力模型**：参考 Project Sid 的 PIANO 思路（无开源实现，需自研轻量版）：情绪/精力/社交需求等内驱状态影响行为选择权重，而不只是 precondition 过滤。与现有 state 体系衔接。
2. **目标生成与里程碑**：长期计划 → 里程碑 → 触发新计划的循环，目标达成后自动生成下一阶段追求，消除「无事可做」。
3. **世界事件注入**：天气已有；增加低频世界事件（学校活动、商圈变化、季节性事件）打破日程惯性。
4. **可观测性**：「活得可信」没有行业评估标准——把 web 界面扩展为行为轨迹回放与诊断视图，既是调试工具，也是未来的演示卖点。

### 完成标志

连续 14 天无人干预运行：无死循环告警、日程熵不单调下降、每天日记内容不重复。这条本身可以作为项目 README 里的硬指标宣传。

## L3：桌宠形态

### 为什么

「有长期记忆的开放性桌宠」的形态落点。桌宠是 view 不是内核：世界引擎不动，新增一个桌面呈现层。这是把「观察角色生活」从 QQ 聊天窗口扩展到桌面的自然一步。

### 方向

1. **技术选型**：Tauri 2（赛道主流：LingChat、PetGPT 均为此路线），透明置顶穿透窗口。
2. **生活现场同步**：桌宠展示她在世界中的实时状态（在写作业/在打工/在睡觉），行为切换驱动桌宠动画/位置变化；她去打工时桌宠离开屏幕——这本身就是叙事，是和所有「等着被搭话」的竞品桌宠的本质差异。
3. **形象**：第一版用精灵图/像素（成本最低、与 web 可视化同源），Live2D 作为后续可选升级。
4. **轻交互**：点击/抚摸等桌宠原生交互映射为世界内事件并进入她的记忆（调研共识：用户介入只有写入记忆才有持续影响）。
5. **主动出现的分寸**：参考 PetGPT 的 5 档说话意愿，把她「什么时候想找你」做成显式分级，避免骚扰感。

### 完成标志

桌宠与 web/QQ 三个入口看到的是同一个同步的生活现场；桌宠交互写入记忆并在后续对话中被她自然提起。

### 明确不做

- 不做语音对话（Open-LLM-VTuber 已做得很好，且语音不是「生活感」的必要条件，先保持范围克制）。
- 桌宠第一版不做屏幕感知/看桌面类功能（LingChat 已有，且与「她的世界」叙事冲突——她活在自己的世界里，不是活在你的屏幕上）。

## L4：生态开放（远期，仅记录方向）

- **记忆协议外露**：person-memory / 双时间轴模型抽象为可复用协议（参考 KokoroMemo 的「本地记忆核心 + 多客户端」定位证明了这类需求）。
- **角色卡兼容**：兼容 SillyTavern 角色卡/世界书导入（32.3k★ 生态的既有内容资产），让用户把自己的 OC 接入 yuiju 世界生活。
- **多角色**：先把一个角色做活做深，再考虑第二角色（ai-town/my_ai_town 的教训都是铺规模导致深度不足）。
- **自部署体验**：单容器 + 本地 LLM（Ollama 兼容）跑通，覆盖隐私敏感用户。

## 横切原则（全阶段适用）

1. **单人可持续性优先**：同类项目 6-12 个月停更是常态，每阶段范围必须能在一个人的维护预算内闭环。
2. **成本预算意识**：记忆检索、importance 打分、内驱力计算都新增 LLM 调用，能进 sleep 时段的不进实时路径，能批量的不逐条。
3. **每个新机制都要落到叙事**：记忆固化=写日记，内驱力=心情，介入=被记住的事。机制不可解释为「她的生活」的，不做。
4. **验证命令**：每阶段代码改动仍按 AGENTS.md 执行 format/lint/type-check。
